# Варианты сжатия статики

## Вариант №1: в момент запроса

Для использования достаточно минимальной настройки:

```Nginx.Conf
gzip on;
gzip_comp_level 6;
gzip_types text/plain text/css application/javascript application/json;
gzip_vary on;
```

Важно понимать, что сжатие «на лету» имеет свою цену — дополнительная нагрузка на ЦП и увеличение времени ответа сервера. Чем выше значение уровня сжатия (gzip_comp_level), тем меньше файл, но выше нагрузка на ЦП. Для продакшена обычно рекомендуют 4-6 как баланс между размером и производительностью.

## Вариант №2: предварительное сжатие

Для использования необходимо добавить сжатие файлов в этап сборки проекта, и включить соответствующую опцию в настройках Nginx:

```Nginx.Config
gzip_static on;
```

Этот вариант позволяет использовать высокий уровень сжатия и при этом быстрее отдавать статику, но увеличивает время сборки.

Сжимать файлы можно как через консольные утилиты, так и через соответствующие плагины для вашей системы сборки, например `compression-webpack-plugin`.

## Алгоритмы сжатия

Помимо `gzip`, дополнительно можно использовать `brotli`, который сжимает на 15-25% лучше, но требует больше ЦП.

По умолчанию Nginx не включает модуль для `brotli` и его необходимо устанавливать отдельно. Пример можно найти в посте [Минимальный фронтовый Dockerfile с поддержкой Brotli](https://t.me/around_dev/57).

## В качестве вывода

Как обычно, не существует идеального рецепта какой из вариантов использовать и с какими параметрами. В каждом конкретном случае нужно пробовать и обязательно замерять результаты.

Тем не менее, для больших проектов, рекомендую выбирать вариант с предварительным сжатием + brotli + максимальный уровень компрессии для обоих алгоритмов.
